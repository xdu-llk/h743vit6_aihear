# AI Hear 最终系统全貌

## 产品定义

AI Hear是一台以STM32H743VIT6为核心的婴儿房边缘AI安全监护终端。核心不是堆叠传感器，而是由H7在本地完成“声音识别、环境状态确认、画面抓拍和告警调度”，ESP8266只承担网络桥接，Android负责远程通知、记录和多设备管理。

国赛保持二分类：`baby_cry / other`。音频不上传，模型准确率只引用历史验证集结果，不把99.67%描述成独立现场实测准确率。

## 四条完整功能链

| 链路 | 输入 | H7板端处理 | 本地输出 | 远程输出 |
|---|---|---|---|---|
| 哭声监护 | INMP441 | 幅度门控、40x96 Log-Mel、INT8 DS-CNN、三级时序复核 | TFT状态、RGB红闪、无源蜂鸣器旋律 | 哭声通知、震动、记录，并触发一次照片上传 |
| 温湿度 | DHT11 | 2秒刷新；连续3次超限/恢复确认和回差 | TFT实时数值；异常红闪，不鸣笛 | 异常通知、恢复记录 |
| 气态污染趋势 | MQ-135 | 120秒预热+60秒稳健动态基线、EMA、相对指数、5次确认 | TFT显示基线指数；异常红闪，不鸣笛 | 异常通知、恢复记录 |
| 颗粒物趋势 | GP2Y1014AU0F + PM2.5 V2.1适配板 | 9次开灯前/后配对差值、双层中值、动态基线、EMA、180%阈值连续7秒确认 | TFT显示相对指数；异常红闪，不鸣笛 | 异常通知、恢复记录 |

三个环境模块各自回答不同问题：DHT11监护舒适度与过热/过冷风险；GP2Y1014AU0F观察烟尘和颗粒物突然上升；MQ-135观察混合气态污染相对正常空气的变化。后两者未做标准气体标定，因此只报告相对指数，不宣称ppm或精确PM2.5浓度。

## 告警优先级与降级

1. 哭声告警优先级最高：先发布告警，再抓取一帧RGB给TFT、抓取一帧JPEG分片给App。照片失败不撤销告警。
2. 环境异常彼此独立，可同时锁存；任一异常都使RGB红灯闪烁并通知App，但不鸣笛、不抓拍。
3. 蜂鸣器播放期间暂停新的哭声推理，音频DMA仍持续采集，避免旋律反向触发模型。
4. TFT、摄像头或网络缺席时，H7声音与环境监护仍继续；ESP长时间无响应时由PA2硬复位，离线队列优先保留告警。

## 本地与移动端

TFT只有一个常态仪表盘，不要求手动翻页：状态区显示 `ARMED/LISTENING/VOTING/ALERT/ENV ALERT`，同时显示声音dBFS、温湿度、PM指数和GAS指数。抓拍成功时临时全屏显示240x240画面，随后自动恢复仪表盘。

Android保持4个Tab：监护、喂养、趋势、分析。监护页支持多设备绑定与切换、开启/暂停哭声监听、停止旋律、手动请求抓拍；趋势页显示7天哭声/喂养折线以及24小时温湿度和空气趋势。每条设备级topic都按ESP MAC生成的ID隔离，照片必须通过分片完整性、CRC32及JPEG SOI/EOI检查后才显示。

## 现场演示主线

1. 展示H7启动、TFT实时刷新和MQ-135/GP2Y动态基线状态。
2. 播放真实婴儿哭声，展示板端三级推理日志、红灯与旋律、App通知。
3. 展示OV2640事件照片先在TFT出现，再在当前设备的App卡片出现。
4. 让DHT11越过阈值或使用软件状态机测试展示环境红灯/App通知，强调环境异常不鸣笛、不抓拍。
5. 切换两台设备，展示定向控制和告警不串设备。

## 当前验证边界

- 已验证：2026-08-08 STM32阶段2.4固件已编译、烧录并校验，BIN `483568B`，ELF text `483064B`、data `496B`、bss `931576B`。焊接整机抓拍后的健康日志保持`stack_free=14036B`、`heap_min=14384B`、`uart_ovf=0`、`pending=0`。
- 已验证：DHT11、MQ-135和GP2Y1014AU0F三套状态机；MQ-135采用固定120秒预热后采集60个样本建立动态基线，约179秒进入normal。GP2Y正式采样使用9次开灯前/后配对差值中值，再进入跨秒中值、动态基线和EMA；USB-C供电实测约14秒进入normal。140%/5秒旧阈值会被自然波动触发，最终候选改为180%/7秒后完成约150秒静置回归，指数主要为84～122，无误报警、复位、UART溢出或消息积压。实际烟尘刺激不作为当前验收阻塞项。
- 已验证：ESP bridge-v5构建，RAM `30160/81920B`、Flash `308739/761840B`；两台ESP均已烧录并联网，设备ID隔离、UART/MQTT、断线恢复和真实照片分片链路通过；Android构建、v2/v3签名、多设备控制、通知、CRC/JPEG校验及真实照片显示通过。
- 已验证：原厂FPC ST7789状态页与抓拍预览、OV2640 SCCB初始化、RGB565本地画面、JPEG抓拍和App端到端照片显示。焊接整机旧版会在抓拍约6秒后触发IWDG复位；运行期看门狗改为约32秒标称并在采集、TFT与分片上传阶段喂狗后，连续5次抓拍均通过。典型单次采集约0.33秒、TFT约0.04秒、21片上传约2.2秒，总耗时约2.5～3.6秒；Broker端重组4907B JPEG并通过CRC32 `df69c344`及SOI/EOI校验。
- 已知边界：公网Broker为QoS 0，30分钟老化中出现1次ESP本地发布失败和3次未知命令回复，均自动恢复且没有复位或积压。演示前必须先确认App设备在线；不在赛前为此重写已验证的通信协议。
